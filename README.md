# FliFli Gesture HID

“翻翻 · 蓝牙手势键盘”是一个 Android 手机蓝牙 HID 自定义输入app。手机会伪装成一个蓝牙 HID 设备，并支持通过手势发送可配置的输入动作。

## 下载与安装

前往 [最新版下载页面](https://github.com/Shalloater/FliFli-Gesture-HID/releases/latest)，在 Assets 中下载 `FliFli-v版本号.apk`，然后在 Android 手机上安装。

## 支持的输入

当前支持的输出类型：

- 键盘按键，如 `A`、`B`、`Page Up`、`Page Down`
- 组合键，如 `Ctrl+C`、`Ctrl+V`
- 媒体键，如播放暂停、上一曲、下一曲、音量键
- Android 控制键，如返回、主屏幕、搜索、音量和电源（效果取决于目标系统和应用）
- 信号序列，一次触发后按顺序发送单键或组合键
- 触控手势（主线版），支持四向滑动、屏幕中心单击/双击，以及十二种屏幕边缘滑动
- 触控透传键盘（主线版），将单指触点按屏幕宽、高比例实时发送

## 触控透传键盘

在「设置 → 新增 → 触控透传」创建独立键盘，可配置名称、横屏/竖屏、背景及振动。从首页连接设备后启动，支持单指点击、双击、长按和拖动。增加手指时立即释放远端触点，并暂停本次输入，抬起所有手指后可继续单指操作。双指向内捏合退出，退出动作不发送到目标应用。手势键盘、电脑键盘均支持同样的双指退出。

默认开启「安全触控区」：在系统保留的顶部、底部区域之间，取最大的 3:4 矩形并居中，以细边界标出。竖屏高度足够时左右铺满，横屏高度不足时等比缩小。没有额外固定留白。框内仍映射目标整屏。可以从框外起滑：框外部分不发送，轨迹第一次穿过边界时才向目标发送按下，起点精确映射到目标屏幕边缘，再继续发送框内轨迹。框外点击或始终不进入框内的滑动均不生效；已在框内开始的触摸移出后仍限制在目标边缘，不会再次按下。关闭安全触控区可恢复整屏映射。

触控区域分别按宽、高比例映射到目标屏幕，不传输远端画面、压力或倾角。长宽比不同时轨迹会拉伸，建议两端使用一致的屏幕方向。触控的具体效果取决于目标系统和应用；iPadOS 等平台仍需实测。

按下、抬起保持顺序，密集移动会合并为最新位置，以约 60 Hz 上限发送，避免积压。取消、退出、切到后台、失去焦点或尺寸变化会释放触点；连接中断会清除待发送输入。发送失败时释放触点并断开，避免停留在按住状态。

触控透传会申请系统允许范围内的边缘返回排除区域，并对返回使用二次确认：首次返回只提示，2 秒内再次返回才退出，中间继续触控会取消确认；退出后恢复普通导航，双指捏合退出继续有效。通知栏、底部主页及其他系统保留手势无法由普通应用彻底禁用，具体边缘排除范围也受 Android 版本和厂商限制。需要更强的 Home 防误触时，可在触控透传设置中开启「屏幕固定保护」（默认关闭）。进入后由 Android 处理确认，部分厂商系统会叠加系统自身的固定说明；应用没有额外确认框。确认固定生效后 Home 不能直接离开，双指退出时解除本应用开启的固定。取消确认或系统未固定时会明确提示。若解除固定后进入锁屏，请在系统的屏幕固定设置中关闭「解除固定时锁定设备」或「取消固定前要求解锁」（如系统提供）；应用没有主动锁屏，也不能修改或绕过这项安全策略。系统取消固定、锁屏等必要通道仍然保留；已由外部策略固定的任务不会被本应用擅自解除。此功能无需额外特殊权限。

1.5.8 加强了退出重进时的触点复位：旧界面回调不能取消新界面会话，退出后补发释放，新会话在释放报告后等待 35 毫秒再发送首个触点。手机的彩色触点和发送 API 成功不能代替受控端实际响应；若特定 Android 设备仍出现重进无响应，需要继续结合两端日志排查。

触点报告仅包含一个当前按下或刚抬起的有效触点，抬手后补发计数为 0 的结束帧。屏幕固定仅保留系统确认，应用不再重复提示确认或固定成功。

预设点击/滑动和实时透传共享单指报告格式。HID 描述符仍保留 Android 10 识别槽位协议所需的额外空记录，实际始终只发送一个触点；这不是额外的透传功能。1.5.10 与 1.5.9 的描述符相同，无需因本次更新删除配对。若从 1.5.6 之前的旧版本更新，应在两端删除旧配对后重新配对，已有键盘和动作配置保留。BLE 实验版目前不支持触控透传，新增入口会显示为不可用。

## 信号选择

在手势动作下方点击「新增动作」，通过「点按」「滑动」标签选择动作类型。点按继续选择次数和区域，滑动选择方向；已配置的滑动以及重叠点按区域仍会标记，避免重复绑定。

点击已有动作会打开「编辑动作」，可分别修改「触发手势」和「发送信号」。更换手势保留当前信号，可在点按与滑动之间切换；当前手势可重新选择，其他重复手势或重叠区域会被禁用。点击编辑窗口的「完成」一次保存两项，取消或返回保留原绑定，条目位置不变。

动作条目与触控信号前显示对应的示意缩略图。长按新增动作、点按区域、已添加动作或触控信号，可查看本地 SVG 演示；点击仍用于选择，演示不会修改绑定或发送信号。弹窗支持暂停、重播、速度切换及拖动进度，文字与配色跟随语言和皮肤，关闭后返回原选择界面。

编辑手势动作时，通过下划线标签切换发送模式，再通过「键盘按键」「Android 控制」「媒体控制」「触控手势」标签选择信号。键盘使用 QWERTY 排列，可横向滑动查看完整键盘，下方有方向键和导航键。按键尺寸保持，横纵间距统一，键盘底板与选择区分开。候选区使用文字框展示，撤销、清空为紧凑按钮；点击「完成」才会应用选择，点击「取消」保留原配置，最后仍需在键盘编辑页点击「完成」保存。

- **单个信号**：点击新信号替换当前候选。
- **组合信号**：依次点击所需按键，以 `+` 连接，同时按下、同时释放。例如依次选择 `Ctrl`、`C`，得到 `Ctrl + C`。再次点击已选按键可移除。支持最多 6 个普通键、修饰键和 1 个媒体/Android Consumer Control 键；触控手势须单独使用。
- **信号序列**：选择当前步骤的信号，点击「＋下一步」继续。勾选「本步骤使用组合信号」后，当前步骤可包含多个按键。点击已有步骤可编辑，也可删除步骤。最多 16 步，步骤间隔默认 100 毫秒，可切换为 0、100、250、500、1000、2000 毫秒。例如 `Ctrl + C → Tab → Ctrl + V`。每一步释放后再执行下一步，连续触发会排队，断开连接会取消剩余步骤。

已有单键和预设快捷键配置保持兼容；五种皮肤与五种语言也适用于新选择界面。
键盘中的 Windows 徽标键显示为 `Win`，右侧徽标键显示为 `R Win`；原有 `kb_meta` / `kb_right_meta` 配置 ID 保持兼容。

手势键盘按各手指自身轨迹识别动作，双指或三指的落指、抬指先后不会产生虚假位移。点按区域取整组手指的中心；连续点击只有在手指数、位置和已配置的连击区域匹配时才合并。只配置单击时立即触发；配置双击或三击时按系统连击时间等待，下一次落指后给予一次正常点按的完成时间。拖出后返回、长按、取消和离开界面不会误算为点按。

墨水屏厂商全局手势资料、证据范围与适合扩展的信号见 [调研记录](docs/eink-gesture-research-2026-10-27.md)。

### 触控手势

主线版使用单指 HID 触摸屏报告。原有四向滑动沿屏幕中心轴移动，单击、双击位于屏幕中心。新增七种边缘信号，按受控屏幕比例定位：左上边缘下滑、左侧边缘右滑、右侧边缘左滑、左下边缘上滑、底部中间上滑、右下边缘上滑和右上角向左下滑。顶部左侧与底部左/中/右使用三等分区域的中点，左右侧边使用垂直中点，斜滑从右上角开始。新增手势从真实坐标边缘按下，再向屏幕内部滑动约四分之一屏，抬起后结束，可放入信号序列。具体阅读器功能由受控端的手势设置决定。

1.5.14 补充顶部右侧垂直下拉、左右侧边各自的上下滑动。顶部右侧下拉从顶部右侧三分之一区域的中点起滑；四个侧边信号从左右边缘垂直中点起滑，沿边缘向上或向下滑动约四分之一屏高。固定滑动段约 208 毫秒，未提供多种长度档位；接收端对亮度、音量等的实际调节量由其自身设置决定。

BLE 实验版保留现有键盘/媒体协议，触控选项显示为不可用。Android 控制键是系统按键，与触摸屏滑动、点击的语义不同。

1.5.6 修复了 Android 的触控槽位兼容问题：触摸屏描述符及容量查询统一预留两个槽位，让 Android 按槽位协议正确保留每帧未变化的坐标；手势仍只发送一个触点。旧版只声明一个槽位时，槽位轴范围仅为 `0..0`，Android 10 要求最大槽位索引大于 0，否则会按另一种协议解析，可能造成坐标丢失或手势无响应。更新后请在两端删除旧蓝牙配对并重新配对，使接收端重新读取描述符；已有手势配置无需重建。此修复已在 Android 11 模拟器验证四向滑动与中心单击、双击到达应用，用户的 Android 10 真机仍需复测。

- 可在设置页创建多个自定义键盘实例
- 当前支持的键盘种类：手势键盘、电脑键盘、触控透传（主线版）
- 首次安装会预置一个名为“阅读器翻页”的手势键盘示例，用户可以继续编辑或删除
- 每个自定义键盘可独立配置名称、振动开关、振动强度和手势动作
- 手势动作按需添加，不会预置全部候选动作
- 点按动作支持单指、双指、三指的单击、双击、三击，并可选择全屏、左半屏、右半屏、上半屏、下半屏

- 滑动动作默认全屏触发，支持单指、双指、三指上下左右滑，以及单指顺时针/逆时针画圈
- 通过标准 HID 报告发送键盘和 Consumer Control 信号

## 重要限制

目标设备必须支持蓝牙 HID 主机，例如：

- Windows 电脑
- macOS 电脑
- Android TV / 电视盒子
- 部分平板、部分电视

普通蓝牙音箱一般不是 HID 主机，不能作为这类输入设备的目标端。

## 系统要求

- Android 9.0 或以上
- 手机系统支持 `BluetoothHidDevice`
- Android 12 或以上需要授予“附近设备/蓝牙”权限

另有独立的 [Android 5 BLE 实验版](compat/README.md)，可与主线同时安装。它需要手机支持 BLE 外设广播、阅读器支持 BLE HID 键盘；目前尚未完成 Android 5 实机与阅读器验证。

## 使用步骤

1. 安装并打开 App。
2. 授予蓝牙/附近设备权限。
3. 打开蓝牙。
4. 在目标设备的蓝牙设置中与手机完成配对。
5. 回到 App，在连接页选择目标设备建立 HID 连接。
6. 进入设置页，新增或编辑自定义键盘。
7. 进入底部“首页”，选择已配置的键盘运行；也可以直接添加键盘。
8. 使用点按、滑动或画圈手势发送该键盘配置的 HID 输入。
