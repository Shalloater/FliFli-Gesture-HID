# 墨水屏全局手势与信号扩展调研

调研日期：2026-10-27。本文区分厂商明确公开的操作、设备功能绑定和基于 FliFli 当前单指 HID 能力的实现建议。没有将不同型号或固件的规则当成统一标准，也没有把本次建议直接加入安装包。

后续实施：根据用户选择，1.5.14 已加入顶部右侧垂直下拉和左右侧边各自的上滑、下滑。四个侧边信号统一使用约四分之一屏高的固定长度。

## 建议的扩展优先级

| 建议信号 | 优先级 | 原因与实现边界 |
| --- | --- | --- |
| 顶部右侧垂直下拉 | 高 | 文石官方明确用于控制中心。与现有“右上角向左下斜滑”不同，现有信号不能替代。可用单指协议实现 |
| 左侧边缘上滑 / 下滑、右侧边缘上滑 / 下滑 | 高 | 共四种，可覆盖前光、音量、对比度调整。手指需沿侧边移动；使用什么功能由接收端的边缘手势设置决定 |
| 定点长按，先提供中心，再允许指定位置 | 高 | 常见于文件属性、菜单、选词等；单指保持按下后抬起即可。长按时长应能适配接收端，不应混同于发送端的长按识别 |
| 定点单击 / 双击，使用九宫格或百分比位置 | 高 | 当前信号只有中心点击；可覆盖特定菜单区、页角、悬浮球。依赖目标界面位置，应作为可编辑坐标而非绑定“截图”等厂商功能名 |
| 自定义单指轨迹与持续时间 | 中 | 可减少逐厂商增加硬编码动作；需要保存可编辑的起终点/路径，并处理旋转和屏幕比例差异。适合后续独立设计 |
| 三指下滑截图、多指缩放/旋转 | 暂缓 | 文石公开支持部分多指功能，但 FliFli 当前只发送单指，用户已要求删除多指透传。不能把多指动作拆成单指序列来冒充同时接触 |
| “全局刷新”“前光开关”“最近任务”等直接功能按钮 | 以厂商配置模板呈现 | 这些是接收端功能，不是统一的蓝牙触摸信号。优先提示用户将接收端功能绑定到现有/新增轨迹；有标准 Android 控制键的可单独验证，不承诺跨品牌通用 |

近期最实用的组合是：**顶部右侧下拉 + 四种侧边竖滑 + 可定位的长按/点击**。这组扩展维持现有单指协议，覆盖面也比重新加入多指输出更符合当前需求。

发送端的“双指单击”等是本机触发方式；信号库中的“触控手势”是在受控端重放的轨迹，两者独立。优化本机多指识别不会恢复已删除的多指透传。
